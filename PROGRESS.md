- **H2 (as-built, split H2a + H2b per user decision)** — the async substrate proper, implementing ADR-0007 D1→D13. **The headline is that FIVE of the ADR's thirteen sub-decisions were contradicted by the installed framework (laravel/framework v13.18.1) and had to be corrected — the ADR itself (`:178`) instructed verifying its API claims at implementation time, and that instruction paid for itself five times.** Every correction is written back into ADR-0007 as a `> Corrected in H2 (as-built)` block, and every one is **proven by mutation**, not argued. **(1) §D4's after-edge is `JobAttempted`, not `JobProcessed`/`Queue::after`.** `Worker::process()` raises `JobProcessed` on the **success path only** (`:561`) and diverts to `handleJobException()` on a throw; `JobAttempted` is dispatched from the `finally` (`:566-570`). Implementing §D4 *literally* therefore leaks the tenant static out of **every job that throws or is released** — the §Context 6 defect merely relocated. Mutation: applying it fails `WorkerContextHygieneTest`'s "clean after a job that THREW" **and only that test**. **(2) §D4 must SAVE/RESTORE, not flush.** Under `QUEUE_CONNECTION=sync` — every CI job — `SyncQueue` raises both events **inline in the caller's stack**, so a blind flush wipes the ambient request context mid-request. A LIFO stack in a `private static` (load-bearing: `Dispatcher::createClassCallable` resolves a **fresh listener per dispatch**, so instance state would silently degrade back into a flush) is correct under both a worker (saved value null ⇒ restore *is* flush) and sync. Deliberately **NOT** gated on `connectionName !== 'sync'` — that gate would make the listener **dead code in every CI job**, i.e. exactly the unverifiability ADR-0007 was written to end. Mutation: a blind flush fails precisely the two sync tests and no worker test. **(3) §D7's `$tries = 3` INVERTS §D9.** `RateLimited` enforces its ceiling with `$job->release()`, and `DatabaseQueue::release()` (`:328`) re-pushes preserving the **already-incremented** `attempts` — so three fairness *deferrals* land the job in `failed_jobs`, converting "this tenant is throttled" into "this tenant's jobs permanently failed". `TenantAwareJob` therefore declares **no `$tries` at all**: `retryUntil()` (time-based, blind to releases) + `$maxExceptions = 3`. ## Gotchas / standing lessons

- **`builder-axe.spec.ts` carried its OWN weaker `forceTheme`, and that was a real latent race — fixed H21d1.** The shared helper in `tests/e2e/support/axe.ts` calls `page.emulateMedia({ reducedMotion: 'reduce' })` FIRST, which collapses the design system's durations to 1ms centrally (`theme-overrides.css` §2.8) so axe cannot sample an element mid theme-flip. `builder-axe` had a local copy that skipped that step. The symptom is unmistakable once you know it: a `color`-transitioned label inside a container whose `background-color` is NOT transitioned reads as the **light** foreground on the **dark** surface — H21d1's `Structure ⇄ Logic` label measured **1.82:1** on CI while the same node settles at **6.96:1**. It presents as a serious `color-contrast` violation in a component that is fine. **If a dark-mode contrast failure names a foreground colour that belongs to the LIGHT palette, it is a transition race, not a palette defect** — check that the spec uses the shared `forceTheme`.
- **A "known flake" can be hiding a real failure — re-run it in isolation before waving it through (found H21d1).** `packages/design-system/src/theme/__tests__/token-references.test.ts` has failed as a 5s timeout in the FULL Vitest run since H21b and is recorded here as a flake. In H21d1 the isolated re-run reported a genuinely undefined `--mds-type-body-font-size` in new CSS — and a dangling token with no fallback makes the whole declaration invalid at computed-value time, so the element scales by *inheritance* under `[data-font-size]` rather than by its type role. Cost of the check: one `npx vitest run <that file>`. **Always run it.**
- **New copy must be checked against the DARK palette specifically (found H21d1).** `--mds-color-danger-text` resolves to `danger-300` in dark, which is **4.22:1** on `bg-surface` at 13px — a real `color-contrast` violation that only the dark axe scan sees. The `status-*-fg` family (`--mds-color-status-danger-fg` / `-warning-fg`) is the on-surface pair, at 8.43:1 light and 6.39:1 dark. When adding status text on a surface, reach for `status-*-fg`.
- **~~`builder-axe` dark fails LOCALLY on `main` too — do not chase it~~ — THAT DIAGNOSIS WAS WRONG, and H21d1 found the real cause.** The note recorded a `color-contrast` failure on `.mds-button--secondary`/`--primary` in dark at all three viewports, reproduced it on `main`, ruled out stale tokens and axe drift, and concluded it was "a local-environment divergence in the rendered dark palette" to be distrusted. It was neither local nor a divergence. **Two real defects were stacked on top of each other.** **(1) A genuine WCAG 1.4.3 failure in the shared dark palette:** `--mds-color-action-primary-bg-hover` was `primary-400` (**3.96:1** against the white `text-on-primary`) and `-bg-active` was `primary-300` (**2.52:1**) — the dark theme LIGHTENED the fill on hover, which is the opposite of what a white-on-fill button needs and the opposite of what the light theme does. The teal accent had carried per-token verification in a comment since G11; the default accent never did. Both now darken (`primary-600` 9.14:1, `primary-700` 13.00:1) and a **test** guards it (`theme-overrides.test.ts`), because a comment is not a guard. **(2) A transition race in the harness:** `builder-axe.spec.ts` carried its own `forceTheme` that skipped the shared helper's `emulateMedia({ reducedMotion: 'reduce' })`, so axe sampled elements mid theme-flip — which is why the failure looked intermittent and viewport-dependent, and why CI passed while local did not. With both fixed, `builder-axe` is **10/10 locally in dark**. **The lesson to carry is the opposite of the one that was written down: a reproducible local a11y failure is evidence, not noise.** Reproducing it on `main` proves it is not the branch's — it does NOT prove it is not real.
- **Never run Pest and Playwright at the same time — they share one database.** `RefreshDatabase` wipes the schema underneath a live e2e run, and the failures land in whatever specs happen to be executing (builder-axe, scopes-axe, templates-axe, public-runtime-offline), which looks exactly like a real regression somewhere unrelated to the increment. Cost this session: two discarded 30-minute runs. Reseed with `php artisan db:seed --class="Database\Seeders\E2eSeeder"` afterwards — **`migrate:fresh --seed` does NOT include the e2e fixture**, so a Playwright run straight after it fails at global-setup's login.
- **Playwright has no `.bin` shim on this host** (the documented `--no-bin-links` consequence) — invoke it as `node node_modules/@playwright/test/cli.js test`, with `E2E_BASE_URL=http://acme.localhost:8080` to reuse the running docker stack.
- **phpstan local OOM** — `composer run quality`'s phpstan OOMs its parallel workers at 128M locally → phantom "undefined property"/relation-nullability errors. CI's Larastan (`disableMigrationScan: false`) scans `database/migrations`, resolves every column → 0 errors → green is the source of truth. For possibly-null relation chains prefer `data_get($m, 'rel.attr')` over `?->`.
- **PHP 8.3** removed `${var}` string interpolation → single-quote grammar snippets in tests (don't let `${...}` interpolate).
- **Windows npm** — a nested design-system esbuild-bin file-lock breaks `npm install <pkg>` → use `--no-bin-links` locally (CI's Linux `npm ci` relinks fine). Consequence (seen in G9b): `node_modules/@rolldown` holds only Linux bindings and `--no-bin-links` leaves no `vitest`/`vite` shim → **`npm run build` and `npx vitest` cannot run on the Windows host** (rolldown `MODULE_NOT_FOUND`, "'vitest' is not recognized"). **`vue-tsc` DOES run** (no native binding), so treat it as the local frontend gate; build + Vitest are CI-only.
- **IndexedDB can't clone Vue proxies (G8b)** — `structuredClone` (every IndexedDB write) throws `DataCloneError` on a reactive Proxy, in real browsers too. Always `plainClone()` (JSON round-trip, `lib/db.ts`) an answer map before a Dexie `put`. Related: happy-dom `Blob`s don't survive `fake-indexeddb`'s `structuredClone` round-trip (assert metadata, not the reconstituted Blob); and `vite-plugin-pwa` `injectManifest` emits an import-free ES bundle that registers fine as a **classic** worker (no `{type:'module'}`).
- **Vitest + repo-root paths (G11)** — suites run under `environment: 'happy-dom'`, whose DOM `URL` global shadows Node's. `fileURLToPath(new URL('../../../../../', import.meta.url))` resolves fine locally but throws `ERR_INVALID_URL_SCHEME` on CI when the target is a **directory** (trailing slash); concrete **file** paths are unaffected, which is why sibling suites using the same pattern pass. Use **`process.cwd()`** for the repo root — Vitest's cwd is its config file's directory.
- **Any Pest test that renders a blade view needs `withoutVite()` (G11)** — the Pest CI job builds no assets, so `@vite` throws `Vite manifest not found`. It passes locally whenever `public/build` happens to exist, which makes it a silent local/CI divergence. Reproduce by moving `public/build/manifest.json` aside before running.
- **Base64url tamper tests** (was "known-flaky", FIXED in G10b2): flipping the LAST base64url char can alias to the same decoded bytes — a 32-byte HMAC is 42.7 six-bit groups, so the trailing char carries 2 padding bits. Flip the FIRST char. Both `GuestRuntimeTest` and `GuestShareTokenServiceTest::tamperSegment` now do; there is no known flaky test left.
