# Ask the Data statistical analysis operations

Phase 4 adds fixed, executable statistical methods to saved private projects. The assistant chooses a typed calculation after reading data definitions and the study design; it should ask only when missing design, units, pairing or denominator information changes what can be calculated. A request never supplies Python, shell commands, SQL or executable paths. Phase 5 geographic/spatial analysis and Phase 6 reports/presentations remain separate.

## Runtime and release gate

The separate Phase 2 Node worker remains necessary. Set server-owned `BHW_STATISTICS_PYTHON` to an **absolute executable path** in a dedicated, operator-managed Python environment. The setting is optional: absent/invalid configuration returns an explicit unavailable calculation rather than an invented result. Chat, sources and research retain their existing behavior. This phase adds no database migration, subscription, user quota or hard spending cap, and changes no shared deployment scripts.

Reference environment: Python 3.12 with pinned NumPy 2.3.5, SciPy 1.17.0, pandas 2.2.3 and statsmodels 0.14.6, from `scripts/statistics/requirements.txt`. Create a dedicated virtual environment and install this requirements file using the operator's supported package source. Before enabling the setting, run `scripts/statistics/test_engine.py` with that exact interpreter under the actual service account. The packaged release must retain `scripts/statistics/engine.py`, the requirements/reference tests, existing extractor/worker and export fonts. Next standalone tracing explicitly includes these files. Python/packages are not bundled or installed by the web application.

**The Windows Server 2016 runtime is an unresolved release gate.** Linux reference/browser tests do not establish supported Python wheels or service-account operation there. The operator must prove a supported runtime on that host, or provide a supported worker host through a separately reviewed deployment change. Do not announce production statistical execution until this is verified. Existing Phase 2/3 worker, originals ACL/backups and schema-snapshot refresh prerequisites still apply.

Execution invokes only the fixed application script via `execFile`, Python `-I` and no shell. The child receives a private JSON manifest path and private output path, with a minimal environment excluding provider/database/session credentials. Each calculation has a 120-second timeout, one numerical-library thread, a 16 MiB input manifest, 4 MiB output and 50,000 input-row bound; temporary files are removed afterwards. These are operational bounds. No arbitrary generated code is enabled, and a Python subprocess is not claimed to be an OS sandbox. Native-library memory is not hard-capped on Windows; monitor the service and size the worker accordingly.

## Supported methods and scientific conditions

| Family | Implemented | Conditions and limits |
| --- | --- | --- |
| Description | Count/missingness, mean, sample SD, min/max, median and quartiles; up to 40 groups | Explicit units/grain and census/sample statement; complete-case exclusion, no imputation. Quartiles use linear interpolation; SD uses n−1. |
| Proportions/rates | Summed numerator / summed denominator; percentage or explicit multiplier; Wilson proportion CI for supported samples | Counts/denominators must be valid and populations disjoint. No mean of row percentages. Wilson CI needs independent unweighted binomial observations. No event-rate CI assumed. |
| Time description | ISO-ordered period summaries and last-period minus first-period observed mean change | Consistent interval/definition statement; missing/invalid periods refused; no interpolation or forecasting. |
| Group comparisons | Welch independent t, paired t, two-sided Mann–Whitney U | Wide numeric x/y columns with an explicit y−x contrast. Independent groups must be confirmed; paired rows require nonmissing unique pair IDs and independent pairs. Minimum three valid observations per group. Mean differences have t intervals; Mann–Whitney reports rank-biserial effect, asymptotic tie/continuity-corrected p, no implemented effect interval. |
| Correlation | Pearson r with Fisher-z CI; Spearman rank correlation | At least four complete nonconstant pairs. Spearman uses seeded pairing permutations below 500 pairs (9,999 resamples, or exact enumeration when smaller), asymptotic p otherwise; no Spearman CI implemented. Inspect outliers, linearity/monotonicity and ties. |
| Categorical comparison | Pearson chi-square and Cramér V; two-sided 2×2 Fisher exact | Individual categorical observations; expected-cell checks gate chi-square. Fisher records category ordering, conditional odds ratio and exact CI; unbounded effects/intervals are refused. No Cramér V interval implemented. |
| Regression | OLS, binary logistic, Poisson with optional log-exposure offset | 1–10 numeric predictors, intercept, full rank and sufficient complete cases. No automatic categorical coding. Reject exact OLS fits without residual variance, non-convergence, separation/extreme GLM coefficients and Poisson dispersion >1.5. Coefficients/OR/IRR, intervals, p and diagnostics are recorded. |

Sampling inference is refused for census/area/aggregate units or undocumented independence flags. The design statement is a disclosed assumption supplied in the typed specification, not something a statistical test proves. The assistant must not invent a sampling design to obtain a p-value. A paired test accepts independent pairs as the observational unit. Weighted/clustered inference, multilevel/spatial models, robust count alternatives, survival, causal estimation and forecasting are unavailable; no silent substitute model runs. Ecological observations can be described without pretending areas are independent sampled individuals.

OLS records R², residual SD, condition number, Breusch–Pagan, Durbin–Watson, residual Shapiro where supported, and maximum Cook's distance. GLMs record convergence, deviance and Pearson dispersion. These are diagnostics for human review, not proof that the model or study design is valid. Conventional model-based intervals apply; robust/clustered SEs are not claimed. Holm p-value adjustment is available across all regression coefficients, including the intercept; confidence intervals remain unadjusted. Separate exploratory analyses have no automatic family-wide multiplicity adjustment and must be interpreted accordingly. Software versions and random seeds/resample counts are retained.

## Complete inputs, provenance and saved replay

Attachment calculations read the whole selected extracted table, never the source viewer's 20-row or search tool's bounded preview. Explicit equality filters are applied before capture. Dashboard calculations allow only registered, approved, queryable columns and read rows/count in one database request, avoiding offset pagination over a changing table. If an API cap, missing exact count or row bound prevents complete extraction, the calculation refuses it and requests explicit narrower filters or a complete exported table. It does not analyse a preview as the population.

A successful calculation is saved with the job: the full selected input rows, typed parameters, source/extraction hashes or dashboard dictionary/filter snapshot, source dates/definitions, canonical input SHA-256 (stable across PostgreSQL JSONB key reordering), engine/software versions, result hash, claims, diagnostics, narrative, table and figure values. These are private project data under existing owner/editor/viewer permissions. The result-field claim IDs bind the AI's numeric prose to the exact calculated values and display precision (`[[resultID:fieldID]]`), replacing raw number-membership auditing for runs containing statistics. Unreferenced/invented numbers or fields are rejected. Ordinary non-statistical conversations retain their existing source/number checks; citation checks still run.

The deterministic English narrative, table cells and figures use the same structured fields and precision. The AI can add explanation, methods and uncertainty using the verified field references. Human review is still required for assumptions, interpretation and causal wording. No semantic validator can prove a study design from a Boolean flag or eliminate all prose mistakes.

The saved-result endpoint rechecks approval/project access and input hash for every download/replay. Re-run executes the saved manifest, compares the result hash including software versions, and reports any difference without overwriting history. Permissions are checked again after a potentially long replay. Viewer access permits replay of their authorized saved snapshot; replay does not start provider calls or create/change a saved job. Deleted source/project results are invalidated by the Phase 3 lifecycle, including manifests referencing deleted source IDs. Existing backup retention applies to saved manifests.

## Scientific output and verification

The private workspace renders titled tables, headed columns, explicit units/missing markers, computed explanatory prose, numbered figure titles, sources and scientific notes. Available intervals and limitations are explicit. CSV and XLSX tables, vector SVG, 3,300-pixel-wide PNG and full JSON calculation manifests are downloadable through the same project ACL. Excel numeric cells retain raw values with matching displayed precision. CSV text is protected against spreadsheet formula injection; Excel text is written as text, not formulas. Figures escape user labels and retain titles, row units, confidence notes and provenance. Missing intervals are not drawn. Reports/decks and new maps are not included.

Formatting follows the applicable WPSAR table/figure checklist: titles, units, abbreviations/notes, source and method disclosure; AI output is not represented as a submission-ready manuscript. WPSAR restricts AI-drafted original prose, so a journal submission needs its own human authorship/disclosure review. Statistical diagnostics and assumption notes are part of the scientific output, not hidden implementation details.

Run normal repository checks and `BHW_STATISTICS_PYTHON=<absolute interpreter> BHW_TEST_DATABASE_URL=<synthetic database> npx vitest run`. The Python reference tests cover Phase 0 independent arithmetic, whole-table versus preview bias, known OLS/logistic/Poisson results, supported method families, repeatability and unsupported designs. CI runs Node/database/browser checks; **the two numerical Python integration cases explicitly skip when that runtime is not provisioned**. They must pass in the reference environment and actual worker environment before release. Use synthetic fixtures for all browser/download/replay checks, never real records.
